# ca$al V2 — DFCL e Portadores Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Entregar no `web/` um DFCL previsto x realizado (meses lado a lado, Prev | Real | %), uma tela de saldo por portador (hoje e projetado) e um lançamento rápido (valor + descrição), alimentados pelas duas planilhas do Pedro.

**Architecture:** Motores puros e testados em `web/src/lib` (`dfcl.ts`, `portadores.ts`, `sugestao.ts`, `planilhas.ts`) que recebem dados e devolvem estruturas; telas finas em `web/src/components/telas` que consomem o store existente (`useLoja`). Campos novos entram como opcionais no tipo `Transacao` e em migrações SQL escritas e testadas só localmente (M17).

**Tech Stack:** Next.js 15, React 19, Tailwind 4, supabase-js, vitest + Testing Library, exceljs (só em script de importação).

**Spec:** `docs/superpowers/specs/2026-10-27-v2-web-dfcl-design.md`

## Global Constraints

- Dinheiro sempre em inteiro `Centavos` (`src/lib/money.ts`); nunca float.
- Sem cor hex fora de `src/design/tokens.css`; usar utilitários `bg-ar`, `text-grafite`, `text-cinza`, `border-nevoa`, `bg-ambar`, `text-ambar-texto`, `--pago`. `npm run cores` deve passar.
- Pessoas: `Pedro`, `Daniele`, `Conjunto`, `PHF`.
- Previsto e realizado nunca se misturam (anti-objetivo).
- Compra no cartão conta no DFCL no mês da compra; pagamento de fatura tem natureza `movimento` e não entra no DFCL (D6, M5).
- Nenhuma migração é aplicada em produção (M17). Dados reais das planilhas não são commitados.
- Textos de interface em português do Brasil.
- `npm run verificar` (cores + tsc + lint + vitest) deve passar no fim de cada task.

## Review Focus

- Competência virando ano (dez → jan) no acumulado e nas colunas do DFCL.
- Previsto 0 com realizado > 0: linha existe, % em branco (sem divisão por zero).
- Parcela n de total cai em meses diferentes e soma o total certo.
- Lançamento `movimento` (Saldo Inicial, transferência, pagamento de fatura) fora do DFCL, mas dentro do saldo do portador.
- Planilha com conta desconhecida: importador reporta, não quebra.
